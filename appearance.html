The bench

Every number below is the one the product ships: the tunings were chosen on a published bench, each candidate rendered live at three settings over a real ISPF panel and judged on a phone. Move the cursor by clicking a cell, or type into a tinted field.

All nine at once

The same panel, the same palette, the same cursor walking the same six stops. Only the effect differs — and four of them are transient, so hover a tile to fire it on demand. The cursors here are held steady rather than blinking, which is the one thing these tiles do that the product does not.

The three on the block, magnified

pulse and raster never leave the cursor cell, and a raster is one-pixel scanlines — at a real cell size they are a texture you sense rather than see. The same CSS at 40px.

Panelwright ships with none. The knob exists once, for fire alone: the verdict when the effects were retuned was that a general intensity control would be three settings nobody could tell apart on eight of the nine.

Two of them are pure CSS. pulse and raster never create a canvas, so they cost nothing per frame — which is why the animated-looking pair are the cheap ones and the still-looking crosshair is cheaper still.

§2   panelwright.screen.theme  ·  .reverseVideo  ·  PW-354..361

Five ways to colour a screen

A 3270 sends colour as an attribute, not a value: blue, red, pink, green, turquoise, yellow, white and the eight extended names. What those names look like is entirely the client's business, and Panelwright answers it five ways.

The 3279 hues are not re-chosen for the editor — they are the exact hex equivalents of the xterm-256 codes the terminal UI's own table uses, so panelwright ui --theme 3279 and a VS Code panel show you the same screen. 3279-light exists because a panel sits in an editor whose theme may be light, where a black screen reads as a hole in the window; the colour that cannot simply be darkened there is white, which in the classic four-colour field scheme means brightest, so its faithful light-ground rendering is a dark neutral.

§3   .fieldTint .markActiveField .hoverFields .currentLine .hiddenFieldHatch .hiddenFieldContent  ·  PW-244 (D25)

Where can I type?

On a real terminal you find out by clicking. Panelwright marks it: a faint wash over every unprotected cell, twice that wash on the field the cursor is in, a third neutral shade under the pointer, and a full-width wash on the cursor's own row. The percentages below are the owner's picks from a three-round visual bench, not a designer's defaults.

No borders, ever

A cell is an inline-block span with an explicit height. A border grows the box and drifts every row below it, so only background, inset shadow and opacity are permissible marks.

A field stays one span

An end-tick variant needed first-cell and last-cell classes — and marking those two cells splits the field, at whose edges a background image restarts, visibly detaching the first and last character from the hatch. The variant was dropped instead.

The underline was rejected on evidence

Hosts already underline: SA highlighting(underscore) renders as one, and ISPF underscores its own input fields with it. Ours would have been indistinguishable. A background is a channel the host is not using.

Dots cost no new information

The field list already carries <hidden, n chars typed> across the wire, so the count was public before the dots were. They never reveal a character — only how many.

The marking rides with the paint. Every host repaint used to post an untinted screen and fetch the field list afterwards, so the tint visibly flashed in on each one — "can it be done as a part of the refresh so we do not display any screen without tint?" Now a repaint builds the render, holds it, fetches the fields and posts one message carrying both, on a 250 ms budget; a slow fetch releases the hold untinted rather than holding a stale frame.

§4   .windowShadow  ·  .backgroundImage  ·  .backgroundImageOpacity

Depth and backdrop

ISPF pop-ups and pull-downs are drawn by the host as box-drawing characters on the same flat grid as everything else. Panelwright detects the box and lifts it: a drop shadow underneath, so a window reads as a window.

Two things about the backdrop are deliberate. It is read from disk once and embedded in the panel, so a web address is not accepted and nothing is ever fetched over the network. And its opacity setting runs 0 to 1 but is hard-capped at 0.4 — the backdrop can never be turned up far enough to make the text on top of it hard to read.

§5   host-sent attributes  ·  the effects Panelwright does not choose

What the wire actually asks for

Four of these are not Panelwright's idea at all. The host sets them, in an attribute byte or an SA order, and the client's only job is to render them — which is still a design decision, because "blink" on a CRT and "blink" in a browser are not the same thing.

Decorations that mean something

These are visual, but they are not decoration: each one is the only way its affordance can announce itself. A real terminal has no hover event and no modifier-click, so the look is the documentation.

§7   panelwright ui  ·  --theme  ·  --plain  ·  --highlight-fields

The terminal UI answers differently

The same screen in a terminal is not the same problem. There is no CSS, no canvas and no guarantee about what the user's palette contains — so the terminal UI makes deliberately different choices, and one of them is the opposite of the panel's.

--theme default
--theme 3279
--plain / NO_COLOR

default uses basic ANSI 16 only, so your own terminal's palette decides the actual hue — a deliberate refusal to override the environment. 3279 forces a black background and 256-colour approximations of the real hues. --plain and NO_COLOR emit zero escape codes of any kind, fall back to ASCII frame characters, and always win over --theme; the environment variable is honoured whatever its value, even empty, because its mere presence is the standard's own trigger.

The editable-field highlight underlines, where the panel tints. Not an inconsistency: the panel's ground is free, but a terminal's background is the one channel a host can genuinely claim with an SA order, and a tint would fight it. That highlight is a plain on/off — it was briefly a three-way smart/all/none cycle, and the owner's acceptance test failed smart outright.

The cursor is hand-drawn in both, for different reasons. A real terminal hardware cursor was built for insert mode and then removed: Ink erases its previous frame relatively, counting rows up from wherever it last left the terminal cursor, so an app-managed cursor that moves to an absolute position outside that bookkeeping makes the next erase start from the wrong row. Measured in a real PTY, three runs: every frame rendered twice. Under --plain the cursor stops blinking and becomes a solid block character substituted into the text — a marker that never vanishes, with no escape codes at all.

§8   panelwright screen --format svg|ansi

Taking the look with you

The renderer is shared, so a captured screen keeps its colours rather than degrading to text:

panelwright screen --format svg --background '#0b0b0d' --out panel.svg

--format ansi writes the escape codes instead, for a terminal or a paste into a log. Both take --out, and the SVG's background is a real choice — none for a transparent canvas, a hex colour, or the default opaque terminal black. One trap worth knowing: rendering an SVG immediately after connecting can capture an empty buffer, because the export can outrun the host's first paint.

§9   the constraints every one of them obeys

Four rules hold the whole layer

Appearance only

Not one effect changes what you type, what is sent, or what the host is told. The wire is identical with every setting on and every setting off — which is what makes the whole layer safe to ship on by default.

Motion yields

Every animated effect turns itself off when the operating system asks for reduced motion — including host-sent blink. crosshair is the exception that proves it: it is exempt because there is no motion in it to reduce.

Legibility has a floor, not a slider

The backdrop caps at 0.4 however high you set it. The raster's halation spills only vertically, never sideways, so it cannot wash out the characters either side. A cosmetic setting is not allowed to make the screen unreadable.

Plain always wins

--plain and NO_COLOR beat every theme, and are startup-only in both directions: once a run starts plain, there is no command to leave it, and no command to enter it mid-session either.
